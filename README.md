# Physics-Informed vs. Physics-Enforced Neural Networks for the Chaotic Three-Body Problem

A comparative study of four neural-network architectures — a plain **DNN**, a **PINN**
(physics-*informed*), and two physics-*enforced* models, an **HNN** (Hamiltonian) and an
**LNN** (Lagrangian) — trained to predict trajectories of the planar Newtonian three-body
problem.

The goal is to measure the trade-off between **raw predictive accuracy** and **physical
consistency** (energy conservation, satisfaction of the equations of motion) when physics is
added to a model either as a soft loss (PINN) or as an architectural constraint (HNN/LNN).

> Companion code for *"Comparing Physics-Informed and Physics-Enforced Neural Networks for the
> Chaotic Three-Body Problem."*

---

## Problem setup

Three equal point masses moving under mutual gravity in a plane:

- Dimensionless units: `G = 1`, `m₁ = m₂ = m₃ = 1`
- Planar motion in the x–z plane (`y ≡ 0`), 18-dimensional state (9 positions + 9 velocities)
- Initial conditions (Algorithm 1 from the reference paper): body 1 fixed at `(1, 0, 0)`, body 2
  sampled from a semi-disk, body 3 fixed by the center-of-mass constraint, all initial
  velocities zero.

All models share a common interface for a fair comparison:

```
input :  (t, x2_0, z2_0)          # time + body-2 initial position
output:  (x1, z1, x2, z2)         # body-1 and body-2 positions at time t
```

## Repository structure

```
.
├── dataset/       Trajectory generation (DOP853), IC sampling, dataset analysis
├── models/
│   ├── dnn/       Baseline 10-layer MLP (no physics)
│   ├── pinn/      Physics-informed residual network (soft physics loss)
│   ├── hnn/       Hamiltonian NN (learns H, enforces Hamilton's equations)
│   └── lnn/       Lagrangian NN (learns L, enforces Euler–Lagrange via torch.func)
├── training/      All training / experiment-runner / tuning scripts (model-prefixed)
├── evaluation/    Metrics + evaluation code, and the metric-definition reference
├── figures/       Plotting / figure- and GIF-generation code
├── configs/       Per-model config.json (hyperparameters) + requirements.txt
└── README.md
```

Each `models/<name>/` folder is self-contained (`model.py`, `dataset.py` data loader,
`train.py`, `metrics.py`, `evaluate.py`, plus `run_experiment.py`/`tune_lnn.py` where present).
The `training/`, `evaluation/`, and `configs/` folders additionally aggregate those files
across models with a `<model>_` filename prefix for convenience.

## The dataset

Generated by [`dataset/pinn_three_body_generator.py`](dataset/pinn_three_body_generator.py):

| Property | Value |
|---|---|
| Integrator | DOP853 (8th-order Dormand–Prince), `rtol=1e-8`, `atol=1e-10`, `max_step=0.01` |
| Trajectories | 1000 (seed 42) |
| Time span | `t ∈ [0, 10]`, 129 timesteps (`dt ≈ 0.078`) |
| State | 18-D `[positions(9), velocities(9)]`, stored shape `(1000, 129, 18)` |
| Split | 80% train / 10% val / 10% test |

Regenerate it with:

```bash
python dataset/pinn_three_body_generator.py     # writes pinn_three_body_dataset.npz
python dataset/analyze_dataset.py               # diagnostics: energy, chaos, IC distribution
```

## The models

| Model | Architecture | Params | Physics mechanism |
|---|---|---|---|
| **DNN**  | 10-layer MLP, 128 hidden, ReLU | 149,636 | none (data loss only) |
| **PINN** | 5 residual blocks, 128 hidden, ReLU | 166,148 | soft loss: `L_data + 0.1·L_physics` (10k collocation pts) |
| **HNN**  | position net + separable Hamiltonian net (64×3) | 167,046 | Hamilton's equations `q̇ = ∂H/∂p, ṗ = −∂H/∂q` |
| **LNN**  | position net + separable Lagrangian net (64×3) | 348,422 | Euler–Lagrange residual via `torch.func` autodiff |

Common training setup: 2000 epochs, batch size 2048, Adam `lr=1e-3`, plateau LR scheduler.
Full hyperparameters live in [`configs/`](configs/).

## Getting started

```bash
# 1. Install dependencies (plus PyTorch — see note below)
pip install -r configs/requirements.txt
pip install torch          # install the build matching your CUDA/CPU setup

# 2. Generate the dataset
python dataset/pinn_three_body_generator.py

# 3. Train a model (run from inside its folder so relative paths resolve)
cd models/dnn && python train.py
cd models/pinn && python train.py
cd models/hnn  && python train.py
cd models/lnn  && python train.py

# 4. Evaluate
python evaluate.py

# 5. Comparison figure across models
python figures/plot_energy_error_comparison.py
```

> **Note:** `configs/requirements.txt` covers the data/plotting stack (numpy, scipy,
> matplotlib, h5py, tqdm). The models require **PyTorch** (with `torch.func`, i.e. torch ≥ 2.0),
> installed separately for your platform from https://pytorch.org.

## Results (test split — lower is better)

| Metric | DNN | PINN | LNN | HNN | HNN-v2 |
|---|---|---|---|---|---|
| **MAE (mean)** | **0.317** | 0.585 | 0.393 | 0.417 | 0.402 |
| **RMSE (mean)** | **1.246** | 1.958 | 1.431 | 1.512 | 1.464 |
| **Rollout Err (mean)** | **0.456** | 0.953 | 0.623 | 0.683 | 0.675 |
| **Energy Drift (median)** | 30.35 | 30.39 | **29.17** | 29.37 | 29.32 |
| **ODE Residual (mean)** | 35.29 | **2.44** | 4.90 | 9.39 | 14.48 |

**Takeaways**

- **DNN wins on raw accuracy** (lowest MAE/RMSE/rollout error) despite having no physics.
- **Physics-enforced/informed models satisfy the dynamics far better** — an order-of-magnitude
  lower ODE residual — with PINN lowest of all.
- **LNN/HNN conserve energy best**; PINN trades position accuracy for physics fidelity.
- Scaling the HNN (HNN-v2, 256h/348K params) narrows but does not close the gap to the LNN of
  equal size, suggesting the Lagrangian formulation suits this problem slightly better.

Full metric tables (including the LNN Euler–Lagrange and HNN Hamiltonian residuals) are in
[`evaluation/metrics_reference.md`](evaluation/metrics_reference.md).

## Metrics reported

MAE, RMSE, relative rollout error, long-horizon error, energy drift, and ODE residual for all
models; plus model-specific diagnostics — Euler–Lagrange residual and Lagrangian-structure
score (LNN), Hamiltonian vector-field residual and Hamiltonian MSE (HNN). Definitions in
[`evaluation/metrics_reference.md`](evaluation/metrics_reference.md).
